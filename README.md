# Party Finder — локальный прототип с общим API

Поиск пати и создание объявлений работают в двух оболочках: публичной и «кабинете». Обе используют один API и одну SQLite-базу. Данные не публикуются в интернете и доступны только на этом компьютере.

## Запуск

Нужен Python 3.11+. В PowerShell из корня проекта:

```powershell
python -m pip install --target .local-packages -r requirements.txt
python server.py
```

Открыть [Party Finder](http://127.0.0.1:8003/party-finder/#ru). Если порт занят, остановить прежний сервер; `python -m http.server` **не подходит**, потому что он не обслуживает API. Для другого порта можно задать `PARTY_FINDER_PORT`.

Проверить общий API без изменения рабочей базы:

```powershell
python -m unittest discover -s tests -v
```

База создаётся автоматически в `data/party-finder.sqlite3`. Она не добавляется в Git. Чтобы начать с чистой базы, останови сервер и удали **только этот файл** (и одноимённые `-wal`/`-shm`, если они остались), затем запусти сервер снова. Это безвозвратно удалит локальные объявления и отклики.

## Что уже работает

- Общие объявления, состав уже собранной пати, вакансии и отклики для публичной и кабинетной страниц.
- Поиск проверяет сервер, класс, уровень и полное покрытие минимального расписания пати. Время переводится между часовыми поясами.
- Контакты лидера открываются игроку после подачи заявки; в результатах поиска они скрыты. Контакты кандидата получает только он сам и лидер объявления после подачи заявки.
- Гость вводит персонажа вручную. Вход выполняется на официальном сайте профиля; проверенная интеграция ЛК с этим API пока не подключена. Тестовых логинов и автоматического заполнения базы нет.
- Лидер принимает, отклоняет и исключает кандидатов; игрок отзывает заявку и может подать её повторно после отказа. Одновременно можно откликнуться в несколько пати.
- Созданное объявление действует 7 суток. Если новый отклик приходит в последние 24 часа, срок продлевается на 24 часа; следующий отклик не продлит его снова, пока до конца не останется меньше суток. После истечения объявление не участвует в поиске.

Сервер слушает только `127.0.0.1`. Гостевая cookie действует 30 дней от создания сессии, срок проверяется и браузером, и сервером. Выход из интерфейса сохраняет её: повторный выбор гостевого режима открывает прежние объявления и заявки. Очистка cookie или истечение срока прекращает доступ; самостоятельное восстановление ещё не подключено.

## Передача разработчику

Контракт и структура таблиц описаны в [docs/INTEGRATION.md](docs/INTEGRATION.md) и [schema.sql](schema.sql). Интеграция настоящих данных персонажа пока не подключена: API принимает только гостевые сессии. Для ЛК разработчик должен добавить серверную проверку авторизации и получение персонажа из профиля; присланный браузером бейдж не является подтверждением.

Перед публикацией обязательны настоящая авторизация, постоянная идентичность гостей (или понятное восстановление), HTTPS, защита от CSRF/спама, ограничение частоты запросов, валидация контактов, миграции БД и решение о сроке хранения персональных данных. Текущий Python-сервер — локальный проверяемый прототип, не готовый production backend.

Сторонние изображения и стили в `assets/` требуют проверки прав на распространение.


## Защита и адреса

Основной адрес — `/party-finder/`, режимы — `?mode=find` и `?mode=create`. Фрагмент `#ru` выбирает русский язык в браузере и не отправляется серверу. `/`, `/party-finder` и `/party-finder/index.html` перенаправляются на основной адрес с сохранением query-параметров.

HTTP раздаёт только разрешённые файлы интерфейса и каталоги ресурсов, без листинга директорий. База и код API закрыты. Запросы ограничены по IP: API — 300/мин, изменения — 60/мин, поиск — 60/мин, новые сессии — 20/час, новые объявления — 10/час. Не больше 32 параллельных обработчиков; тайм-аут соединения — 10 секунд. Лимиты хранятся в памяти процесса.

Для списка и поиска поддерживаются query-параметры `limit` (по умолчанию 50, максимум 100) и `offset`. Запросы с чужим Origin/Host отклоняются; JSON требует `Content-Type: application/json`. При развёртывании укажите доверенные хосты в `PARTY_FINDER_HOSTS` через запятую и включите `PARTY_FINDER_SECURE_COOKIE=1` за HTTPS. Ограничения у reverse proxy должны учитывать реальные IP; произвольным X-Forwarded-For сервер не доверяет.


На одну гостевую личность и на один IP допускается максимум 5 активных непросроченных пати и 5 разных персонажей с ожидающими заявками. Персонаж определяется сервером и ником без учёта регистра; класс не влияет на идентичность. Число разных пати, в которые откликается один персонаж, не ограничено, но сохраняются краткосрочные лимиты запросов. Создание, восстановление и повторная активация проверяются в одной транзакции с записью.

Ожидающая заявка действует 7 суток с отправки. После срока API показывает `expired`, её нельзя принять, она не занимает лимит, игрок может отправить новую. Принятые заявки не истекают и продолжают занимать место. В БД у исторических ожидающих записей сохраняется `pending`; эффективный статус определяется `expires_at` при чтении и проверках. Миграция добавляет поля без удаления данных. Для записей, созданных до появления учёта IP, исходный IP неизвестен; лимит владельца действует, IP назначается при обновлении/реактивации.


Повторная подача того же персонажа в ту же пати разрешена через 1 минуту после предыдущей, с проверкой владельца и IP. Другие пати не затрагиваются. История заявок в `/bootstrap` загружается порциями (`limit`, `offset`, `applicationsHasMore`, `applicationsNextOffset`), принятые участники действующих своих пати включаются дополнительно для управления составом. Список своих объявлений ограничен 100 последними с приоритетом активных.

Закрытые заявки старше 90 дней и ожидающие заявки, истёкшие более 90 дней назад, очищаются при старте и ежечасно порциями по 1000. Принятые заявки сохраняются. Неизвестный или отсутствующий IANA-пояс заменяется на `Europe/Kyiv`; расписания сравниваются поминутно, включая смещения на 30/45 минут. Полное JSON-тело читается до начала транзакции, а транзакция завершается до отправки ответа.


Параметры пагинации проверяются до SQL: `limit` — 1–100, `offset` — 0–10000; отрицательные, слишком большие и дублированные значения дают 400. Некорректный Unicode, нулевой символ в текстовых полях и чрезмерно глубокий JSON отклоняются. Поиск сначала отбирает подходящие свободные вакансии в SQL, один раз вычисляет минуты кандидата и использует ограниченный кэш повторяющихся расписаний в рамках запроса.

`PARTY_FINDER_TRUSTED_PROXIES` — список IP/CIDR доверенных прокси, по умолчанию пустой. Только от этих адресов читаются `X-Forwarded-For` и `X-Forwarded-Proto`. Цепочка IP разбирается справа налево до первого недоверенного узла; входные заголовки внешнего клиента не должны передаваться прокси как достоверные без добавления реального адреса. Для HTTPS за доверенным прокси cookie получает Secure автоматически и включается HSTS. Дополнительно можно принудительно задать `PARTY_FINDER_SECURE_COOKIE=1`. Origin проверяется с учётом фактической доверенной схемы.
